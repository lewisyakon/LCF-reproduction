# 子问题四：Cache 通信方法实验设计

## 一、实验主线

**按原文方案训练 → 第一阶段：统一测试与基础开销记录 → 第二阶段：传输量—回答质量 trade-off。**

各方法保留原文训练数据和处理方式，使用统一任务、模型配置、初始信息和评分标准测试。记录回答质量、模块参数量、通信量，以及各项操作在实际测量设备上的计算开销。

## 二、数据集与原论文设置

### 2.1 数据集

| 领域 | 统一测试集 | 内容与指标 |
|---|---|---|
| 数学 | [GSM8K](https://github.com/openai/grade-school-math) | 多步算术文字题；最终答案准确率 |
| 证据问答 | [HotpotQA](https://hotpotqa.github.io/) | 多段落证据问答；Answer EM、F1，固定作为本项目测试集 |
| 代码生成 | [HumanEval](https://github.com/openai/human-eval) | 根据函数签名和 docstring 生成 Python 代码；pass@1 |

其他数据保留原文训练用途：[OpenHermes 2.5](https://huggingface.co/datasets/teknium/OpenHermes-2.5) 是约百万条混合指令与对话，覆盖问答、数学、代码等任务；MATH-algebra 为竞赛代数题，ARC-C 为科学推理选择题；ROPES 为背景规律与情境阅读理解，MuSiQue 为多跳问答，QASC 为双事实科学选择题，StrategyQA 为带支持事实的 yes/no 推理问答。

### 2.2 原论文设置

原文参数量仅作量级参考，本实验按三组配置分别统计。

| 论文 / 方法 | 原文主要模型配置 | 训练数据与输入方式 | 转换模块参数量 |
|---|---|---|---|
| [C2C](https://arxiv.org/pdf/2510.03215) | Qwen2.5-0.5B、Llama-3.2-1B、Qwen3-4B-Base → Qwen3-0.6B；另有扩展配置 | OpenHermes 2.5 前 500K；两端相同输入、Cache 对齐融合；部分规模分析另用 MMLU | 默认 Qwen2.5-0.5B → Qwen3-0.6B 约 477.8M，采用 LCF 论文统计 |
| [Dense](https://arxiv.org/html/2606.13594v1) | Qwen3-4B、8B、14B 两两有向组合，共 6 个方向 | GSM8K、MATH-algebra、ARC-C；Cache 重构后做生成训练，生成阶段已知/未知源输入各 50% | 原文未集中报告总量，按实现计数 |
| [LCF / LCF-X](https://arxiv.org/html/2605.22863v2) | LCF：Qwen2.5-0.5B → Qwen3-0.6B；LCF-X：Qwen3-0.6B → Qwen3-0.6B | LCF：OpenHermes 2.5 的 500K 子集、相同输入；LCF-X：HotpotQA-bridge、共享问题与互补证据 | LCF（d=128）约 19.4M；LCF-X 含池化约 25.93M |
| [Dual-Cache / XKV](https://arxiv.org/html/2608.20617v1) | Qwen3-0.6B、Gemma-3-1B、Llama-3.2-3B 的 3×3 有向网格 | ROPES、MuSiQue、QASC、StrategyQA、HotpotQA-bridge；共享问题与选项、分配互补证据 | 跨配置汇总：XKV 约 4.55M，异构 LCF-X 约 19.03M |

## 三、统一实验条件

### 3.1 模型配置

三组均完成两个阶段的主实验。

| 编号 | 上游 Sender | 下游 Receiver |
|---|---|---|
| M1 | Qwen3-0.6B | Qwen3-1.7B |
| M2 | Qwen3-0.6B | Qwen3-4B |
| M3 | Qwen3-4B | Qwen3-0.6B |

冻结基础模型，固定模型版本、Tokenizer、聊天模板、thinking 设置、精度和生成方式。LCF-X 使用 XKV 论文描述的异构扩展。

### 3.2 测试输入

$q$ 为完整任务；$C_S/C_R$ 为两端额外证据，$C$ 为全部证据；$p_0$ 为不含当前题目信息的固定前缀。

| 协议 | 上游初始输入 | 下游初始输入 | 测试范围 |
|---|---|---|---|
| P1：共享完整输入 | $q+C$ | $q+C$ | 三个测试集，作为完整输入已知的参照 |
| P2：互补证据 | $q+C_S$ | $q+C_R$ | HotpotQA，两端各一个支持段落与四个干扰段落 |
| P3：全部证据在上游 | $q+C$ | $q$ | HotpotQA |
| P4：完整任务只在上游 | $q+C$ | $p_0$ | 三个测试集 |

- GSM8K、HumanEval 保留完整题目，$C=\varnothing$，P3 与 P1 合并；HotpotQA 固定证据及分配方式。
- LCF-X 在数学、代码任务中将完整题目 Cache 作为一个 span；XKV 直接池化完整题目 Cache。下游对 $q$ 或 $p_0$ 形成非空 Cache 后更新，P4 作为原文协议的扩展测试。
- 方法需要额外原文时，补传字节、Cache 重建和新增 Prefill 全部计入；不支持的协议与适配实现分别标注。

### 3.3 训练与测试约定

按第二节的原文方案训练，记录实际数据组合、预处理和权重来源。每种方法、每个模型方向、每档通信配置固定一份权重，跨测试任务和协议复用；原文若分别训练多份权重，先用独立验证集选定一份。

训练、验证与测试样本分离，检查混合语料与测试题的重合。验证集用于选择权重、提示词、group 排序和通信配置；HumanEval 用于冻结后的测试。记录同数据集训练、同领域训练及协议扩展情况，结果对应当前训练方案的适用性。

## 四、统一记录指标

| 类别 | 记录内容 |
|---|---|
| 实验配置 | 方法、模型方向、权重、训练来源、测试样本、协议、$K/k/d$、传输位置、输入/输出 Token 数 |
| 回答质量 | 任务原生指标、相对同条件文本基线的差值与置信区间，保留逐样本输出 |
| 模块参数量 | 池化、投影、转换、融合等模块的参数量及去重后的总量，标明两端部署位置 |
| 通信量 | 原始 KV、实际发送表示、生成消息、补传原文和元数据的字节数；记录张量形状与精度 |
| 上游计算开销 | Prefill、文本消息 Decode、筛选、池化、投影、转换、打包及必要搬运的耗时 |
| 下游计算开销 | 本地/新增文本 Prefill、解包、恢复、广播、融合、最终 Decode 的耗时 |
| 测量设备与环境 | 各操作实际执行的设备型号、执行后端、软件版本、精度、batch；各项耗时报告均值、P50、P95 |

## 五、第一阶段：统一测试与基础开销

E1—E6 均覆盖 M1—M3，在 P1—P4 适用范围内共用测试清单，并记录第四节全部指标。

| 编号 / 方法 | 实验落实 | 实际发送内容与计算位置 |
|---|---|---|
| E1：T2T | 固定提示词；消息生成不设人为 Token 上限，记录容量限制与异常终止；下游缺少 $q$ 时显式携带完整 $q$ | 上游生成文本消息，下游 Prefill 后回答；统计完整文本字节和两端耗时 |
| E2：C2C | 按原文训练；P1 直接融合，其他协议核对输入对齐要求；需要原文补齐时单列完整路径 | 完整源 KV，以及必要补传文本；下游转换、融合与新增 Prefill |
| E3：Dense | Cache 重构与生成两阶段训练，生成阶段已知/未知各 50%；同一权重测试全部适用协议 | 上游转换后的完整 Cache；记录转换、位置处理、下游 Prefill 与 Decode |
| E4：基础 LCF | 按原文训练，初始 $d=128$；采用与 C2C 相同的对齐核查和原文补齐规则 | 完整源 KV；联合转换与融合先放在下游 |
| E5：LCF-X | 按原文 HotpotQA 互补证据训练，初始 $d=128$，适配三组模型 | 上游池化后的最终源摘要；下游广播、转换与融合 |
| E6：XKV | 按原文数据与证据组织训练，记录实际训练组合；初始 $k=3$、$d$ 为下游 hidden width 的 1/8 | 上游每层每 KV head 的 $k$ 个 K/V slots；下游池化、层映射、联合记忆与 Cache 更新 |

存在缺失输入时，另记录“直接转发缺失原文、下游回答”的文本保底路径，与生成消息路径分别报告。C2C/LCF 的原文补齐保留原有任务信息；无法完成对齐的条件记录为不支持。

## 六、第二阶段：传输量—回答质量 trade-off

沿用第一阶段的训练方案、模型和测试清单。各档均保留质量与开销结果，达标点作为后续系统设计的候选。

| 编号 / 方法 | 实验落实 | 重点记录 |
|---|---|---|
| V1：Dense 保留组数 $K$ | 固定 E3 权重，用训练/验证数据确定并冻结转换后 Cache 的 group 排序；保留比例取 $\{1/16,1/8,1/4,1/2,3/4,7/8,1\}$，按整组取整 | 质量、实际发送字节、筛选和恢复耗时 |
| V2：Dense 固定集合 | 比较不同校准子集的排序稳定性；每个方向固定一份排序，跨任务和协议复用，并与同组数随机选择比较 | 集合重合情况、跨任务/协议质量及随机选择差距 |
| V3：LCF／LCF-X／XKV 传输位置 | 固定权重，比较集中执行、发送源摘要/slots、发送源侧投影贡献；先核对操作依赖和执行一致性 | Cache、Logits、质量与数值误差；各位置的通信量及两端处理耗时 |
| V4：LCF／LCF-X 维度 $d$ | 取 $d\in\{64,128,256,512\}$，各档按原文方案重新训练，在 V3 验证可行的位置测量 | 质量、模块参数量、实际通信量及池化/投影/融合耗时 |
| V5：XKV slot 数 $k$ | 取 $k\in\{1,2,3,4,8\}$，固定 $d$，各档重新训练；主曲线发送源 slots，同时记录可行的投影路径 | 质量、模块参数量、slots/投影载荷及两端处理耗时 |

**V3：发送位置说明**

固定同一份权重与 $k/d$，比较以下计算划分。源侧投影贡献只完成联合线性降维中与上游输入有关的部分；下游加上本地贡献后，再执行后续非线性处理。

**LCF / LCF-X**

| 发送位置 | 发送内容 | 下游剩余处理 |
|---|---|---|
| 上游 Prefill 后（LCF / LCF-X） | 完整源 KV Cache | LCF-X 先完成源 Cache 的两级池化；随后与本地 Cache 联合降维，执行 MLP、升维与门控更新 |
| span 内池化后（LCF-X） | 每层、每个 KV head、每个 span 的 K/V 摘要 | 跨 span 池化为全局摘要，再广播、联合降维、执行 MLP 与 Cache 更新 |
| 跨 span 池化后（LCF-X） | 每层、每个 KV head 的一组全局 K/V 摘要 | 将摘要广播至下游序列长度，再联合降维、执行 MLP 与 Cache 更新 |
| 源侧线性投影后（LCF） | 每个接收层、每个对齐 Token 的 $d$ 维源侧贡献 | 对本地 Cache 做对应投影，与源侧贡献相加，再执行 MLP 与 Cache 更新 |
| 全局摘要的源侧线性投影后（LCF-X） | 每个接收层一份 $d$ 维源侧贡献，无需按下游 Token 重复发送 | 将源侧贡献广播至下游序列，与各 Token 的本地投影相加，再执行 MLP 与 Cache 更新 |

**XKV**

| 发送位置 | 发送内容 | 下游剩余处理 |
|---|---|---|
| 上游 Prefill 后 | 完整源 KV Cache | 两端 Cache 池化、源层映射、联合降维、记忆生成与 Cache 更新 |
| 上游池化后 | 每个源层、每个 KV head 的 $k$ 个 K slots 与 $k$ 个 V slots | 本地 Cache 池化、源层映射、联合降维、记忆生成与 Cache 更新 |
| 源层映射后 | 已对齐到下游层数的源 K/V slots | 本地 Cache 池化，与源 slots 联合降维，生成记忆并更新 Cache |
| 层映射后的源侧线性投影后 | 每个接收层一份 $d$ 维源侧贡献 | 本地 Cache 池化并投影，与源侧贡献相加，再完成 MLP、层间记忆处理与 Cache 更新 |
| 层映射前的共享线性投影后（需验证可交换条件） | 每个源层一份 $d$ 维源侧贡献 | 在 $d$ 维空间完成层映射及相应偏置处理，合入本地投影，再完成后续记忆生成与 Cache 更新 |

各位置先与集中执行结果核对 Cache、Logits 与回答质量。XKV 最后一种划分需确认线性投影在层间共享，且与层映射的运算顺序可以等价交换。

| 变量 | 对实际通信量的影响 |
|---|---|
| Dense 的 $K$ | 只打包发送选中的 groups 时，载荷随 $K$ 变化 |
| LCF／LCF-X 的 $d$ | 下游内部降维不改变已发送载荷；上游先投影并发送贡献时，载荷才随 $d$ 变化 |
| LCF-X 的 span 数 | 原方法最终聚合成一个摘要，本轮通过 $d$ 与传输位置研究数据量 |
| XKV 的 $k$ | 发送源 slots 时载荷随 $k$ 变化；发送固定 $d$ 的源侧投影贡献时，$k$ 主要改变质量与计算 |

每个“数据集 × 模型方向 × 协议”分别绘制质量—实际传输字节数曲线，按传输位置区分并标注 $K/k/d$。各点附模块参数量、分项耗时及测量设备；传输量不变时另比较质量—计算耗时。

不限长 T2T、原文转发、可运行的 C2C 和各方法默认配置作为参照。保留未达标点呈现失效边界，固定配置在验证集选定后，统一报告三个测试集上的结果。
